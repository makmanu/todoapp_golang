# Users API

Требуются Go 1.26+, Docker Compose и GNU Make. Go с включённым
`GOTOOLCHAIN=auto` загрузит подходящий toolchain автоматически.
Версии библиотек закреплены в `go.mod` и `go.sum`.

## Запуск

```sh
cp .env.example .env   # только если .env ещё не создан
# Заполнить POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB.
make env-up
make migrate-up
make env-port-forward
make run
```

HTTP слушает `127.0.0.1:8080`. При запуске с хоста `make run` задаёт
`POSTGRES_HOST=localhost`; из Docker-сети используйте `todoapp-postgres`.
Приложение читает переменные окружения; файл .env загружает Make.
`go run ./cmd/todoapp` требует заранее экспортированных переменных.

`POSTGRES_TIMEOUT` ограничивает подключение и каждую операцию БД;
`POSTGRES_MAX_CONNS` ограничивает пул. SIGINT/SIGTERM останавливают приём
новых запросов, активные запросы получают до `HTTP_SHUTDOWN_TIMEOUT`.
После истечения срока соединения принудительно закрываются.

После работы: `make env-port-close`, `make env-down`.
Данные сохраняются; `env-cleanup` удаляет их только после подтверждения.
Make создаёт игнорируемый `out/go.mod`: Go не должен обходить файлы
PostgreSQL в `out/pgdata`, принадлежащие контейнеру.

## Контракт

| Метод и путь | Результат |
| --- | --- |
| POST /api/v1/users | 201, пользователь и заголовок Location |
| GET /api/v1/users?limit=10&offset=0 | 200, JSON-массив пользователей |
| GET /api/v1/users/{id} | 200, пользователь |
| PATCH /api/v1/users/{id} | 200, обновлённый пользователь |
| DELETE /api/v1/users/{id} | 204 без тела |

Ошибки: 400 — некорректный запрос, 404 — пользователь не найден,
409 — конкурентное изменение или пользователь связан с задачей,
500 — внутренняя ошибка. Тело: `{"error":"not found"}` (аналогично для
остальных кодов); внутренние ошибки не передаются клиенту.

```sh
curl -i http://127.0.0.1:8080/api/v1/users \
  -H 'Content-Type: application/json' \
  -d '{"full_name":"Иван Иванов","phone_number":"+79991234567"}'
```

Ответ:
```json
{
  "id": "6f8dcdb1-1765-4e3d-ae37-45c714d02a92",
  "version": 1,
  "full_name": "Иван Иванов",
  "phone_number": "+79991234567"
}
```

Имя: 3–100 Unicode-символов без NUL. Телефон: null либо плюс и
9–14 цифр (первая — не ноль), всего 10–15 символов.
Это правило одинаково для домена и новой миграции 000002.
Начальная миграция 000001 не изменяется.

PATCH различает три состояния:
- `{}` сохраняет поля; успешный UPDATE увеличивает version.
- `{"phone_number":"+79990000000"}` записывает номер.
- `{"phone_number":null}` удаляет номер.
- `{"full_name":null}` запрещён.

`version` в запрос не передаётся: сервис читает текущую версию и выполняет
UPDATE с условием по ней. При двух перекрывающихся PATCH только один
сохраняется, второй получает 409. Это защищает read-modify-write на сервере;
последовательный PATCH от клиента со старым экраном не обнаруживается,
поскольку клиентская версия/If-Match пока не входит в контракт.

Без limit/offset соответствующее ограничение отсутствует. Значения
неотрицательные; limit=0 возвращает []; порядок фиксирован по id.
Пустой список всегда [], не null.
Неизвестные JSON-поля, лишний JSON после объекта и тело более 1 MiB дают 400.

CORS разрешает любой origin без credentials для локальной разработки.
OPTIONS получает 204. X-Request-ID возвращается в ответе и используется
в логах; некорректный или отсутствующий идентификатор заменяется новым.
Логи содержат метод, путь, статус и длительность, без тела запроса.

## Архитектура

`cmd/todoapp` вручную собирает config → pool → repository → service → HTTP.
Домен в `internal/core/domain` использует только стандартную библиотеку и
общие sentinel-ошибки. UUID v4 генерируется через crypto/rand.
JSON Nullable находится в транспорте, доменный Nullable не знает о JSON.

Интерфейсы сервиса и репозитория объявлены у потребителей. Репозиторий
зависит от нейтрального pool; только адаптер pool/pgx импортирует драйвер.
У каждой SQL-операции есть timeout, параметры передаются плейсхолдерами.
Обновление проверяет version и увеличивает её атомарно.

Маршруты объединены под /api/v1; middleware применяются в порядке
CORS → RequestID → Logger → Trace → Panic → Handler.

## Проверка

```sh
make test               # модульные тесты с -race; интеграционный тест пропускается без DSN
make vet
make build              # out/todoapp
make test-integration   # отдельный временный PostgreSQL, удаляется после тестов
```

Интеграционный тест проходит CRUD через HTTP, три состояния PATCH,
невалидные данные, пагинацию, DELETE при внешнем ключе, два одновременных
PATCH (200 + 409) и откат/повторное применение миграции телефона.
Он не подключается к базе из .env.

Для самостоятельного запуска задайте TODOAPP_TEST_DATABASE_URL, указывающий
на **пустую одноразовую базу**: тест создаёт и удаляет схему todoapp.
